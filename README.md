# olga.io — гостевой дом «Ольга»

Одностраничный сайт с простой заявкой на бронь: гость оставляет **имя и телефон**,
заявка сохраняется в **Google Таблице** и приходит **модератору в Telegram**.

## Файлы

| Файл | Назначение |
| --- | --- |
| `index.html` | весь сайт (вёрстка, стили, логика формы) |
| `gas/Code.gs` | обработчик заявок: Google Таблица + Telegram-бот |
| `gas/appsscript.json` | манифест веб-приложения Apps Script |
| `modern-guest-house-website.zip` | архив прежней версии сайта (бэкап, не используется) |

## Как работает заявка

```
Форма на сайте (имя + телефон + ID заявки)
   │  1) POST, JSON в text/plain (см. «Важно про CORS»)
   ▼
Google Apps Script (doPost)
   ├──► лист «Заявки»: Дата и время | Имя | Телефон | Источник | Telegram | ID заявки
   └──► бот отправляет сообщение модератору (TELEGRAM_CHAT_ID)

   │  2) сайт спрашивает doGet?action=check&id=… — «строка с таким ID есть?»
   │  3) если подтверждения нет — резервный путь doGet?action=book&… (та же запись)
   ▼
Гость видит «Заявка сохранена» ТОЛЬКО после подтверждения из таблицы.
Иначе — «Заявка НЕ отправлена» и кнопка с готовым текстом в Telegram.
```

`no-cors`-ответ непрозрачный, поэтому «запрос ушёл» ≠ «заявка записалась»: раньше сайт
писал «отправлено» вслепую, и заявка могла молча не попасть в таблицу. Теперь успех
подтверждается чтением таблицы по ID. Если веб-приложение недоступно, сайт сам открывает
готовое сообщение в Telegram (`t.me/share/url`) — заявка не теряется.

### Быстрая диагностика (30 секунд)

1. Откройте в браузере адрес веб-приложения с параметром `action=diag`:
   `…/exec?action=diag` → должен прийти JSON:
   - `"sheetOk": true` — таблица доступна и заявки пишутся;
   - `"telegramConfigured": true` — Telegram настроен;
   - при проблеме: `"code": "NO_SPREADSHEET" | "WRITE"`, `"message"` с причиной.
2. В редакторе Apps Script запустите функцию `diagnose` — она покажет имя таблицы, лист,
   число заявок и ссылку на таблицу, куда реально пишет скрипт.

## Настройка с нуля (один раз, ~15 минут)

### 1. Создайте Telegram-бота

1. В Telegram откройте **@BotFather**, отправьте `/newbot`, придумайте имя и юзернейм.
2. Скопируйте выданный **токен** вида `1234567890:AA...`.
3. Напишите вашему боту любое сообщение (например, `/start`) — иначе бот не узнает ваш `chat_id`.
4. Узнайте `chat_id`: либо откройте в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и возьмите `result[0].message.chat.id`,
   либо после шага 4 запустите в Apps Script функцию `logChatIds()` (см. ниже).
   Если уведомления нужны в группу — добавьте бота в группу, `chat_id` будет отрицательным.

> Можно указать несколько получателей через запятую: `12345678, -1001234567890`.

### 2. Создайте Google Таблицу

1. Откройте [sheets.new](https://sheets.new) — создастся новая таблица.
2. Назовите её, например, `Заявки — Ольга`.
3. Больше ничего делать не нужно: лист `Заявки` и шапку скрипт создаст сам при первой заявке.

Колонки листа `Заявки`:

| A | B | C | D | E | F |
| --- | --- | --- | --- | --- | --- |
| Дата и время (МСК) | Имя | Телефон | Источник | Telegram | ID заявки |

- **E** — `Отправляется…`, `Отправлено`, `Не отправлено` или текст ошибки: видно, дошло ли уведомление.
- **F** — служебный ID, по нему сайт проверяет, что строка действительно появилась,
  и не создаёт дубль при повторной отправке. Скрывать колонку можно, удалять — не нужно.

### 3. Вставьте код в Apps Script

1. В таблице: **Расширения → Apps Script**.
2. Откройте `Code.gs`, удалите содержимое и вставьте код из [`gas/Code.gs`](gas/Code.gs).
3. **Настройки проекта** → включите «Показывать файл манифеста appsscript.json»,
   откройте `appsscript.json` и замените содержимое на [`gas/appsscript.json`](gas/appsscript.json).
   (Там заданы часовой пояс `Europe/Moscow`, доступ «все» и нужные права.)
4. Сохраните проект (Ctrl/Cmd + S).

### 4. Задайте секреты (свойства скрипта)

**Настройки проекта → Свойства скрипта → Добавить свойство:**

| Свойство | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | токен от @BotFather |
| `TELEGRAM_CHAT_ID` | ваш `chat_id` (или несколько через запятую) |
| `SPREADSHEET_ID` | *необязательно* — только если скрипт создан отдельно от таблицы; id из URL таблицы |

> ⚠️ Токен бота **нельзя** вставлять в `index.html` — он станет виден всем.
> Только в свойствах скрипта.

### 5. Проверьте в редакторе Apps Script

В выпадающем списке функций по очереди запустите (при первом запуске согласитесь с правами:
«Дополнительно → Перейти на страницу проекта»):

- `setup` — создаст лист с шапкой и отправит тестовое сообщение в Telegram;
- `diagnose` — покажет, в какую таблицу/лист пишутся заявки и настроен ли Telegram;
- `logChatIds` — если не нашли `chat_id` на шаге 1, покажет его в журнале;
- `testRequest` — полный цикл без сайта: строка в таблице + сообщение боту.

Если в колонке E появилось `Не отправлено` — смотрите **Выполнения** (Executions) Apps Script:
там будет причина (обычно неверный токен или `chat_id`).

### 6. Опубликуйте веб-приложение

1. **Развернуть → Новое развёртывание** → тип **Веб-приложение**.
2. Выполнять от имени: **Я (Me)**. Кто имеет доступ: **Все (Anyone / Anyone, even anonymous)**.
3. Нажмите **Развернуть**, скопируйте URL — он заканчивается на **`/exec`**.

> После любого изменения `Code.gs` обязательно **Развернуть → Управление развёртываниями →
> изменить → Новая версия → Развернуть**, иначе `/exec` продолжит работать со старым кодом.

### 7. Подключите сайт

В начале блока `<script>` в `index.html` вставьте URL в `CONFIG.API_URL`:

```js
API_URL: "https://script.google.com/macros/s/AKfy.../exec",
```

Это **не секрет** (URL всё равно виден в коде страницы), но он открывает приём заявок —
не публикуйте его в открытых чатах. Токен бота остаётся только в Apps Script.

### 8. Финальная проверка

1. Откройте сайт: индикатор в блоке бронирования станет зелёным —
   «Онлайн-отправка работает — заявка уйдёт в таблицу и Telegram».
   Если он красный — сайт проверил таблицу и она недоступна: откройте `…/exec?action=diag`
   и смотрите `code` (раздел «Заявка не приходит в таблицу»).
2. Заполните имя и телефон, отправьте заявку. Успех показывается **только** после ответа
   `doGet?action=check` с `"saved": true`, то есть когда строка реально в таблице.
3. Убедитесь, что в листе `Заявки` появилась строка (в F — ID заявки), а модератору
   пришло сообщение бота. Если в E написано `Не отправлено` — заявка на месте,
   но Telegram не ушёл (см. журнал выполнений).

## Важно про CORS

Apps Script **не отвечает на preflight-запрос `OPTIONS`** и не отдаёт CORS-заголовки,
поэтому обычный `fetch` с `Content-Type: application/json` с сайта не сработает.
В `index.html` используется обходной путь:

- заявка уходит «простым» запросом: `Content-Type: text/plain;charset=utf-8`, `mode: 'no-cors'`,
  `redirect: 'follow'`; Apps Script читает JSON из `e.postData.contents`;
- ответ непрозрачный (`opaque`), поэтому подтверждением считается только ответ
  `doGet?action=check&id=…` с `"saved": true` (JSONP), а не сам `fetch`;
- все проверки и резервная отправка идут через JSONP: `doGet` отвечает скриптом
  `callback({...})` (либо чистым JSON, если `callback` не передан).

Не меняйте `text/plain` на `application/json` и не убирайте `mode: 'no-cors'` без
полноценного прокси с CORS-заголовками.

## Если что-то не работает

### Заявка не приходит в таблицу

Идите по шагам сверху вниз — каждый пункт отсекает половину причин:

1. **`…/exec?action=diag`** в браузере.
   - `sheetOk: false` → смотрите `code`:
     - `NO_SPREADSHEET` — скрипт не привязан к таблице (создан через script.google.com,
       а не через «Расширения → Apps Script» в таблице) или неверный `SPREADSHEET_ID`.
       Лечится: создайте скрипт из таблицы **или** задайте `SPREADSHEET_ID`;
     - `WRITE` / `CHECK` — нет прав на запись: при первом запуске не выдан доступ
       «Google Таблицы», либо таблица удалена/переименована/на другом аккаунте.
   - `sheetOk: true`, но заявки не появляются → запустите `diagnose` и проверьте,
     **в какую именно** таблицу пишет скрипт (ссылка в журнале). Часто владелец смотрит
     одну таблицу, а скрипт пишет в другую.
2. **Сайт и скрипт — одна версия.** Если `?action=diag` отвечает без `sheetOk`/`code`
   (старый формат) или на `/exec` отдаётся ошибка — развёрнута старая версия:
   **Развернуть → Управление развёртываниями → изменить → Новая версия → Развернуть**.
3. **Права развёртывания:** «Выполнять от имени: Я», «Кто имеет доступ: Все».
4. **URL в сайте:** `CONFIG.API_URL` в `index.html` оканчивается на `/exec` (не `/dev`
   и не `/edit`) и совпадает с адресом из «Управления развёртываниями».
5. **Журнал:** в Apps Script откройте **Выполнения (Executions)** — по каждому `doPost`
   видно ошибку, если она была. Пустой журнал = запрос до скрипта не дошёл (п. 2–4).
6. **Проверка без сайта:** запустите `testRequest`. Если строка появилась — проблема
   в публикации/URL, а не в логике.

| Симптом | Что проверить |
| --- | --- |
| Гость видит «Заявка НЕ отправлена», строки нет | `…/exec?action=diag` → `sheetOk`, `code`, `message` (см. выше) |
| Раньше сайт писал «отправлено», а строки нет | Развёрнута старая версия `Code.gs` без подтверждения — обновите код и развёртывание |
| Индикатор красный, заявки уходят в Telegram вручную | URL оканчивается на `/exec` (не `/dev`); доступ «Все»; новая версия развёрнута |
| Строка в таблице есть, бот молчит | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, боту написали `/start`; журнал выполнений |
| `Не найдена таблица` | Скрипт создан отдельно — задайте `SPREADSHEET_ID` |
| Ошибка CORS в консоли | Где-то остался `application/json` в `fetch` — см. раздел выше |
| Заявка не появилась после правки кода | Создайте новую версию развёртывания (шаг 6) |
| Дубли строк на одну заявку | Не удаляйте колонку F (ID заявки) — по ней работает защита от дублей |

## Безопасность

- Токен бота и `chat_id` — только в Script Properties.
- URL веб-приложения можно вставлять в сайт, но любой, кто его узнает, сможет отправить
  заявку. При появлении спама добавьте в форму скрытую ловушку (honeypot) или reCAPTCHA.
- Политика конфиденциальности в `index.html` — заглушка: замените на реальный текст до запуска.
